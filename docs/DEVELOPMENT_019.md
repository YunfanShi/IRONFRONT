# IRONFRONT 0.19.0 开发与 QA


本轮在已同步 GitHub main 的 0.18.1 上开发大厅、AI 小队和第二张地图，统一版本为 0.19.0。保留 Three.js 架构、单人、最多八人 LAN、征服、前线推进及原有八类载具。资源为原创程序几何与现有音频；不增加商城、虚假进度或新玩法。

## 实施顺序与完成状态

1. 核对 main 与本机 0.18.1，冻结 CPU 基线和旧地图回归。
2. 完成原创机库大厅及独立作战、配装、设置、房间页面。
3. 修复小队槽位、交替掩护、可达救援、维修与重生装甲调度。
4. 建立地图上下文，完成 Dust Horizon 与 LAN 地图一致性。
5. 执行完整 QA，记录限制，生成 DOCX 与两个 ZIP，提交 main。

## 大厅与操作

首页显示当前兵种与武器的 3D 方块角色、地图玩法和四个小队槽位；单人与房间分开。作战页使用实际地图截图，提供两张地图及两种玩法。配装仍使用既有持久配置；LAN 保留 IP、端口、房间码、链接、阵营、逐人准备与短时重连。预览 24 FPS 上限，页面隐藏停止动画，进入准备界面先销毁旧大厅预览，准备界面停止隐藏战场绘制；退出取消 RAF、移除监听器、释放几何材质及 renderer；WebGL 缺失仍能操作菜单。

## AI 实际行为

四人小队保留四兵种职责，队长阵亡后由存活成员接任；成员槽位按 ID 持久保存，队形朝向任务方向。接敌时分成推进与掩护组，每七秒交换；狙击手保持远距射界，医疗兵先验证救援路径并拒绝隔墙短距离救援，撤离优先于狙击守位和掩护停驻；工程兵接近停驶受损车辆后实际维修。普通队员更新队形终点不再每次重启意图；新诊断分别记录任务切换、队形更新、真实位移、凝聚度、交替、救援、维修及卡路。

修复了两个实际问题：装备不在范围内时原先也消耗完整冷却，工程兵走近后不能及时维修；基地重生装甲因仅允许 55 米内登车而无人使用。现在无动作重试为一秒，最近且路线可达的 AI 能返回空闲装甲车；事件期间加快集结，仍需真实到达才能占据驾驶位。指挥官继续只使用己方报告及衰减情报；精锐只提高协作与持续性，不提高伤害或授予透视。

联机普通位置修正限制在每秒两米内，避免二十赫兹权威快照造成镜头跳跃；死亡、部署、换座等明确重定位仍立即同步。

## 多地图

MapDefinition 集中保存地图尺寸、基地、据点、道路、碰撞、停车区、地形函数、视觉参数和支持玩法；每场 Battle 独立持有 MapContext，导航与渲染均使用该上下文。旧配置缺省为 Industrial Frontier，未知 mapId 明确拒绝。地图切换经原战局销毁流程清理导航、场景、HUD 与部署状态，不使用可污染其他房间的全局当前地图。

Industrial Frontier 保留原 720 尺寸、地形、五据点、碰撞及停车坐标。Dust Horizon 为 950×950，峡谷、工业遗址、聚落、道路枢纽、能源设施各占一据点；两端基地、主车道、两侧步兵路线、岩壁掩体、废墟梁柱、能源罐及荒漠植被构成原创环境。两图均支持征服与前线推进及现有八类载具。房主广播并锁定 mapId，客户端按同地图创建战局，重连恢复；未知地图与不兼容版本阻止进入。

## 限制与后续

浏览器采用 Chrome 软件 WebGL，功能检查通过不等于实机 FPS 达标。原有 Three.js 分块约 502 kB 的构建提示仍存在。LAN 检查运行真实服务与本机多客户端，覆盖局域网 IP、准备与重连，但尚未由两台独立设备验证 Wi-Fi 隔离及防火墙。前线样本的胜率仅覆盖三个固定种子；路线和结束逻辑通过，仍需更多种子调校平衡。

Dust 寻路失败样本为 0–40 次，旧地图为 0–1 次；全场最高 40 次。失败计数不等于持续卡死，但不宣称全部无失败，峡谷与装甲拥挤处仍需长时观察。Metro Collapse、Tidebreaker、新玩法与新载具类别均未实现。

## 运行与分发

npm install 后 npm run lan 默认启动 7878；朋友使用房主的 http://局域网IP:7878 地址，无需各自安装包。单人可运行 npm run dev。十一首 MP3 只进入本地完整包（public 与 dist 共 22 个文件项），公开源码包和 GitHub 仅保留导入清单；不得把私有音乐上传公开仓库。
