# 0.18.1 性能优化与验收

本轮在0.18.0网页游戏上做CPU与实例化渲染优化，按性能修复升至0.18.1。保留原画质、射速、AI决策频率、视野、阵营和载具规则。

## 基线

任务开始本机main与origin/main均为34637fd；八个本机游戏目录的src/server/scripts和版本文件与该提交逐字节一致（0差异）。该main与0.18.0交付代码树相同，Unity开发已移出main。

## 实现

### 寻路

使用稳定优先队列替代A*开放列表的线性最小值扫描和splice。相同优先级按插入顺序处理，保留原路径选择。导航节点和工作缓冲复用，起终点只搜索80米范围内网格。返回路径独立复制，外部修改不能污染缓存。

### 遮挡

将线段与建筑AABB的两个轴检测展开，移除每个建筑、每次视线判断生成的临时数组；保持平行线、端点忽略范围、padding与碰撞判断规则。

### 人物实例

按可见部件紧凑写入实例矩阵。第一人称自身、车内乘员、过期尸体、未取出的装备及人类专用标识按原显隐规则排除。空实例批次不绘制，只上传活跃矩阵范围；切换装备、阵营或视角后重新填充。

## 固定基准

预热1轮、测量5轮，比较中位数（毫秒）。几何命中结果、路径hash、两种战局状态hash均与冻结0.18.0相同。

| 工作负载 | 优化前ms | 优化后ms | 耗时下降 |
|---|---:|---:|---:|
| 遮挡/碰撞20,000次 | 16.55 | 3.44 | 79.2% |
| 步兵路径315次 | 68.07 | 27.25 | 60.0% |
| 32v32模拟120秒 | 1109.63 | 1028.98 | 7.3% |
| 64v64模拟120秒 | 2654.00 | 2230.70 | 15.9% |
| 32v32士兵矩阵120次 | 30.80 | 25.70 | 16.6% |

浏览器32v32静止人物样本：活跃人物批次76→64，人物实例2432→2016，未使用装备实例320→0。120次人物更新在每轮内同步执行，用于隔离CPU矩阵生成；不包含GPU绘制时间。未降低人物动画频率。

## 验收

- Strict TypeScript、120单元测试、43Chrome浏览器测试、LAN与生产构建通过。
- 8/16/32/64自动战局、默认32v32/500票战局通过。
- 新增70条冻结步兵/坦克路径、250条含平行/退化线段的遮挡结果，以及路径修改后缓存隔离检查。
- 新浏览器用例验证隐藏装备不提交实例、取出维修工具显示、收回后隐藏和换阵营重新分组；原载具座位、复活/救援、导弹、装备和房间重连全套保留。
- 命令日志、5次测量原始数值与截图见docs/qa和docs/screenshots。

## 复现

```bash
npm run check
npm run test:browser
npm run compile:logic
node scripts/benchmark-performance.cjs
```

可用脚本第二参数指定冻结基线.logic-build目录。比较双方运行环境、种子、输入和计时窗口必须一致；不要同时运行重负载进程来估算FPS。

## 边界

本次数字为同一台Mac、Node v24.15.0与Chrome的短时CPU样本；不是整帧GPU时间或长期FPS承诺。32v32/64v64各模拟120秒，用完整士兵、车辆、据点、弹药/投射物状态指纹比较；此对照不代表所有种子和整局都穷尽验证。完整战局由现有回归另行验证。Three.js分块大于500kB的既有构建警告仍在，未引入LOD、动态画质或新的地图。
