# 0.18.0 房间界面与局域网连接恢复

## 目标与基线

本轮在 0.17.0 的单人和局域网战局上改进建房、入房、准备和断线流程。开始前本地 `main` 为 `8a76609508956eaae158f7d5c232e96fe2df2649`，工作区干净；GitHub `origin/main` 仍为 `329a0d2289d7023ff78a262e1c34aad9a6d1c048`。0.17.0 的本地提交因当前机器缺少 GitHub HTTPS 认证而未能上传，故本轮从已完成且已验证的本地 0.17.0 继续，不回退其 AI 功能。

原准备室用一行文字显示玩家状态，建房与入房控件位于长设置页底部。客户端 WebSocket 意外断开后直接返回主菜单；房主离开会使余下玩家失去开始权限。倒计时期间掉线也不会重置准备阶段。

## 界面改动

- 主菜单增加“联机房间”直达按钮。局域网区域分为创建和加入两张卡片，主机地址独立呈现；切换战局、画面等设置页时保留地址、房间码、AI 补位和默认阵营。
- 六位房间码自动转大写。把完整分享链接粘贴到房间码框时，同时填入地址和房间码。连接检查、创建和加入期间显示明确状态，重复提交按钮暂时禁用。
- 准备室逐人显示阵营、房主、配装中、已准备或正在重连；显示在线人数、倒计时与开始条件。准备按钮可取消准备。晚加入正在进行的战局仍可确认配装并部署。
- 房主可复制局域网分享链接或房间码；复制 API 不可用时使用浏览器选择复制的后备方法。暂停和准备界面都可查看连接信息。游戏内显示连接、重连和失败状态；联机暂停菜单清楚说明“重新开始”会离开房间并进入单人战局。
- 房间卡片、配装、连接信息采用一致的暗色战术面板、明确的操作层级和窄屏单列布局。单人游戏入口保留。

## 联机状态与协议

房间服务使用 0.18.0 版本检查；旧网页或旧房主进程不能混用。创建房间时随机房间码会检查现有房间避免碰撞。公开状态接口只给出房间数量和阶段，不列出邀请码。最初的房主令牌只能使用一次；房主尚未连接时，先来的普通加入者不会获得房主权限。HTTP 房间查询在倒计时或满员时返回具体原因；最多 8 个席位，短时断线保留席位也计入上限。

服务器首次入房下发仅属于该玩家的随机恢复令牌。意外断线时保留身份、准备状态、房主角色及私有玩家状态 30 秒，同时让原实体遵循既有 AI 接管或 AI 关闭规则；成功重连后重新接管同一玩家 ID。网页自动间隔重试，在断开期间暂停本地战局推进与输入预测，避免过时画面继续模拟。主动返回主菜单使用明确的离房关闭码，立即释放席位。

房主主动离开时，最早进入的在线玩家继承房主权限；房主短时意外掉线期间保留恢复机会，30 秒未恢复后转交权限。客户端收到角色变化会更新准备室开始按钮。倒计时期间任何人断开，房间退回准备阶段；所有席位在线且准备后才能重新开始。房主调整玩家阵营时，准备阶段会清除被调整玩家的准备状态，防止换队后直接开战。

## 验证

- TypeScript 和 Vite 生产构建通过；现有 117 项单元测试通过。
- `scripts/verify-core.cjs` 中 8/16/32/64 人战局及默认 32v32、500 票战局均结束，导航失败为 0。
- `scripts/test-lan.cjs` 用实际 WebSocket 验证双客户端权威状态、异常断线后同 ID 回连、主动离房后的房主移交、初始房主令牌一次性使用、倒计时掉线取消、载具席位失效后的私有状态清理，以及原有阵营、弹药、射击和 8 人容量规则。
- `tests/room-ui-018.spec.ts` 在 Chrome 中验证界面字段保留、分享链接粘贴、房间准备/取消、复制、客户端自动重连及房主移交。完整浏览器回归结果记录在根目录 `QA_REPORT.md`。

## 限制与操作

恢复只适用于同一房主进程仍在运行、浏览器持有恢复令牌且在 30 秒内重新连上的情况；服务进程重启或断线超过保留期需要重新入房。本功能是局域网房间恢复，不提供公网匹配、跨 NAT 穿透或持久账号。房主和朋友须都使用 0.18.x 网页与服务；升级时停止旧 `npm run lan` 进程并重新启动。实际跨两台物理电脑的 Wi-Fi、防火墙和系统本地网络权限仍需用户环境验证。
