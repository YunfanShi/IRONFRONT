# 0.21.0 Unity 步兵战术：目击记忆与可达掩体

## 目标与基线

本轮继续 `codex/unity-port` 分支，开始时本地与 GitHub 均为 `d1a450b`、版本 `0.20.0`。`main` 保持网页游戏的移植前内容。上一版已能为双人小队动态分配据点，但士兵只追逐眼前目标，敌人消失后立即忘记位置；受击时也不会利用地图掩体。本轮继续移植网页 AI 的局部战术原则，保持“未看到的敌人不提供实时坐标”的情报边界。

## 实现

- `PrototypeSquad` 保存成员实际目击的最后敌方坐标，7 秒后过期。无敌人可见时，第一名队员仅在该位置靠近当前据点且自己可以到达时短暂搜索；第二名队员继续执行据点任务。搜到报告位置后清除旧线索。搜索位置是目击时的副本，不随被遮挡目标移动。只有当前确实可见的敌人才会被射击。
- `PrototypeBot` 区分推进、驻守、交战、搜索、转移掩体、掩体内和阵亡状态。前排队员倾向推进到 24 米内，后排队员保持约 38 米距离；士兵失去敌人后回到当前小队命令。受击或低血量且有目击线索时，士兵尝试进入掩体；不增加虚构减伤。
- 新增 `PrototypeTactics.cs`：只从现有建筑与箱体旁选候选点，检查不碰撞、敌人方向被几何体遮住、与队友预留位置分离，并调用真实步兵导航验证路径。最多检查评分最高的六个候选点，选不到就维持原行动。掩体随威胁移动可能失效，失效后清除旧路线再重新选择。
- B/C 据点外围增加七处低矮箱体，确保双方步兵从实际接近路线有掩体可用，并保持占领圈内部开放。HUD 小队面板显示双方正在找掩体或搜索的士兵人数，便于直接观察战术状态。
- 新功能按 `ForAgent.md` 将开发分支版本升至 `0.21.0`。网页玩法没有重写；网页包、菜单、房主状态与房间版本门槛同步。升级网页房主时需重启服务，`0.20.x` 与 `0.21.x` 房间不互通。

## 验证

- 使用 Unity 6000.5.10f1 随附 Roslyn、.NET Standard 2.1 和 UnityEngine 引用静态编译全部八个 Unity C# 脚本，通过。
- 将实际 `PrototypeLayout`、`PrototypeNavigation`、`PrototypeTactics` 源码放入独立 .NET 场景桩，检查 B/C 两侧四组交火位置。四组均找到候选掩体；复验点不与障碍碰撞、敌方视线被遮挡且 A* 路线存在。该场景桩不模拟 Unity 物理或整局行为。
- 独立指挥官场景桩还验证小队共享最后目击坐标、7 秒后过期，以及搜索完清除线索。包括上一版指挥分配在内的八项场景检查通过。
- 在本机 Unity 6000.5.10f1 的 `SampleScene` 实际 Play 到短局结束：新箱体显示、双方小队命令继续变化，据点、票数及玩家 HP 更新；HUD 曾同时显示蓝队 2 人、红队 3 人处于掩体状态。最终红队 0 票、蓝队剩 35 票，出现蓝队胜利提示；Console 0 错误、0 警告。这验证了一局可结束，不代表长期平衡或独立构建已完成。
- 网页 TypeScript 检查、117/117 单元测试、Vite 生产构建、双客户端 LAN 自动回归通过。生产构建仍有 Three.js 分块略超 500 kB 的已有提示；结果见根目录 `QA_REPORT.md`。

## 当前范围

本轮只增加步兵局部战术。掩体是地图几何和路径驱动的短时站位，尚无卧倒、探头动画、压制、医疗、补给或兵种装备；Unity 联机和载具也仍需后续阶段。搜索只使用最近目击坐标，不是预测敌人实时位置。
