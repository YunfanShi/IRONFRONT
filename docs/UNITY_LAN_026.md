# 0.26.0 Unity 局域网房间与房主权限

## 目标与基线

本轮从 `codex/unity-port` 的 0.25.0 继续。此前 Unity 原型已有单人征服战局、四兵种、双方 AI、R4 侦察车和 U8 运输车，但 Unity 玩家之间没有房间或同步协议。网页的 `/play` 房间承载另一套更完整的战斗模型，因此本轮在同一 Node LAN 服务上新增独立的 `/unity` 协议 `unity-1`，避免把 Unity 状态误交给网页客户端。二次开发继续留在分支，不合并 `main`。

## 使用方法

1. 房主在仓库根目录运行 `npm run lan`，让防火墙允许本机局域网连接。终端会打印 `http://局域网IP:7878`。同机测试可使用 `http://127.0.0.1:7878`。
2. 在 Unity 6000.5.10f1 打开 `UnityProject/Assets/Scenes/SampleScene.unity`，点击 Play；也可以运行构建出的 macOS 应用。出击界面点击 `LAN ROOM / CREATE OR JOIN`。
3. 房主输入服务地址并点击 `CREATE ROOM`。界面显示六位房间码。只把局域网地址和房间码告诉其他 Unity 玩家，不分享房主令牌。
4. 玩家填写房主的局域网地址及房间码，点击 `JOIN ROOM`。所有人选择蓝队或红队并点击 `READY`；房主可把其他玩家移队或踢出。房主可以设置 100、300、500、800 票。修改票数或阵营会清除相应准备状态。
5. 全员准备后，房主点击 `START MATCH`。服务端进行 3 秒倒计时，房主开始模拟战斗。Unity 房间最多 8 名真人，并保留现有固定的双方 8 名 AI 步兵；车辆也由房主模拟。

网页房间与 Unity 房间不能互相加入。Unity 首轮联机统一使用突击兵 IF-27；访客目前只能作为步兵行动，不能占用载具驾驶、机枪或后排座位。

## 权限与数据流

| 操作 | 房主 | 普通玩家 | 服务端规则 |
| --- | --- | --- | --- |
| 选择阵营、切换自己的准备状态 | 可以 | 可以 | 只能修改自己；房主可改其他人的阵营 |
| 调整战局票数、开始战斗、踢人 | 可以 | 不可以 | 按服务器记录的连接身份校验，拒绝客户端自报房主 |
| 发布玩家/AI/车辆/据点/票数快照 | 可以 | 不可以 | 只有房主连接可发，快照序号必须递增 |
| 提交移动、朝向、冲刺和射击输入 | 房主本地直接模拟 | 可以 | 服务器绑定提交者 ID，限制数值范围、序号和每秒最多 20 次 |
| 房主异常掉线后的权限 | 30 秒内可凭恢复令牌重新接入 | 不会晋升 | 房间暂停；房主主动离开则关闭房间 |

创建房间时服务器签发一次性房主令牌。Unity 客户端从服务端 `welcome` 与 `room` 消息读取角色，界面只展示相应控制；真正的授权在 `server/unity-room.cjs` 中执行。玩家发送 `host`、`role`、`room`、`snapshot` 等伪造字段不会获得权限。服务器不使用玩家消息中的自报玩家 ID、位置、血量或命中结果。普通玩家的输入经验证后以服务器指定的 ID 转交房主；房主根据自己的时钟推进移动、射击、伤害、复活、AI、载具和占点，再向所有访客广播战场快照。

房主是本轮战场权威，所以房主机器也能影响战斗结果；这符合房主权限高于普通玩家的要求。Node 服务只负责连接、权限、房间状态和转发，尚未在服务器上执行 Unity 物理与完整战斗模拟。局域网协议使用 HTTP/WebSocket，不应直接暴露到公网上。

## 实现范围

- `server/unity-room.cjs` 管理 Unity 房间、人数和预留席位、准备与倒计时、房主令牌、踢人、设置和快照转发；`server/lan.cjs` 将 Unity HTTP/WS 路由接到现有服务，网页 `/play` 路由保持独立。
- `PrototypeLanClient` 负责 Unity HTTP 创建/查询、WebSocket 收发、消息长度限制、主线程队列、30 秒意外断线恢复和主动离房。房主/访客权限由服务器消息确定。
- `PrototypeRoomMenu` 显示房间地址、房间码、成员与阵营、准备状态、票数和房主专属按钮。出击界面可进入房间，战斗 HUD 显示房间、角色和连接状态。
- `PrototypeRuntime` 在房主端推进战局与采集快照，访客端只应用快照；`PrototypeRemotePlayer` 将已验证的访客输入转成房主端步兵移动与射击，并参与 AI 选敌和据点统计。访客冲刺在房主端重演；弹药、射击频率、射程与伤害由房主端 IF-27 规则决定。
- 版本按 `ForAgent.md` 的新功能规则升到 0.26.0，网页包、房主状态、网页客户端版本门槛、Unity 应用版本一致。新脚本纳入 macOS 构建的必需文件校验。

## 当前限制与下一步

本轮已打通 Unity 客户端通信和房主权威步兵战局，但没有完成两台独立计算机长时间人工对战验收。访客不能驾驶或乘坐载具；职业选择、能力、手动换弹、装备、载具座位和乘员显示尚未形成完整的多人同步。战斗中访客与房主仍按 Unity 原型的简化射线、地形和 AI 规则运行，访客本地移动会被房主快照纠正，弱网下可能出现位移抖动。下一轮应增加输入预测/插值、持续双机实战与断线恢复测试，并逐步加入职业装备及多人载具座位授权。
