# 0.32.0 Unity 初始界面改版

## 目标与范围

参考现有网页游戏的大厅、作战、配装、设置结构，为 Unity 单人入口制作一套完整的全屏菜单。保留已完成的工业前线战场、征服规则、兵种系统、玩家代号和 LAN 房间入口；本轮只调整首次进入游戏时的界面与预览，不修改战斗、复活、房主权限或联机协议。之前制作的赤砂走廊地形图与概念图保留，Unity 作战页将它和攻防模式标为“开发中，暂不可选择”，避免菜单显示尚未实现的玩法。

## 界面与操作流程

1. 打开 `UnityProject/Assets/Scenes/SampleScene.unity` 并按 Play，进入全屏大厅。左侧显示当前工业前线行动与四人小队卡片，右侧是兵种模型预览；底部持续显示玩家代号、单人游戏和联机房间入口。
2. 顶部选择“作战”，查看当前可玩的工业前线、五据点线路图与征服规则。赤砂走廊和攻防模式仅展示计划状态，点击它们不会切换实际战局；单人游戏仍进入工业前线的征服模式。
3. 顶部选择“配装”，可选突击兵、医疗兵、侦察兵、工程兵。右侧模型按所选兵种实时重建，装备卡读取 `PrototypeInfantryRoles` 当前默认武器的伤害、射速、弹匣及有效射程。此页是现有默认配装的展示与兵种选择，没有增加武器编辑功能。所选兵种会带入单人战斗。
4. 顶部选择“设置”，可调整主音量并查看常用操作。主音量通过 Unity `PlayerPrefs` 留在本机。玩家代号延续 0.31.0 的本机保存逻辑。
5. `F1` 至 `F4` 切换四个菜单页，数字键 `1` 至 `4` 快选兵种，`Enter` 进入单人战斗，`L` 打开原有 LAN 房间。编辑玩家代号时，快捷键不会误触发；在输入框按回车只结束编辑。鼠标也可以操作顶部页签、兵种卡和底部按钮。

## 实现说明

- `PrototypeFrontend` 继续使用项目原有 960 × 600 逻辑画布和 IMGUI 绘制。统一的顶栏与底栏在四页之间保持位置，信息面板沿用深色、青蓝色的战术视觉。部署、濒死与战内 HUD 使用既有实现。
- 新增 `PrototypeMenuPreview`：独立摄像机将现有 `PrototypeSoldierVisual` 渲染到 512 × 512 的 `RenderTexture`，配合低多边形机库地面、立柱与物资箱作为启动页背景。预览对象放在独立图层，不带玩家、AI 或网络脚本；所需材质从已有游戏材质克隆，关闭页面或销毁运行对象时释放纹理和材质。菜单预览只改变展示颜色，不修改战场人物模型。
- UI 文案中可玩的地图、模式与配装来自当前游戏状态；开发中的项目不可选择。版本号从 `Application.version` 获取。按仓库版本规则将网页包、LAN 服务版本显示与 Unity 包版本同步到 `0.32.0`；Unity 房间消息协议仍为 `unity-3`。

## 验证

- Unity 6000.5.10f1 编辑器刷新脚本后，在 `SampleScene` 中 Play：大厅、作战、配装、设置均可显示。作战页的未来地图与未来模式保持不可选择；设置页操作提示完整。Console 为 0 错误、0 警告。
- 在配装页用数字键切换兵种，模型与默认武器数据随之变化；从医疗兵配装按 `Enter` 能进入现有单人战斗，战内武器与所选职业一致。
- `tsc --noEmit` 与 `tsc -p tsconfig.logic.json` 通过；`scripts/verify-core.cjs` 的 8/16/32/64 人模拟及默认 32 对 32、500 兵力值的完整战斗均通过。
- Vitest 13 个测试文件、117 项测试通过。完整 AI 战局在与其他耗时检查并行时触发默认 20 秒测试超时；单独以 `--testTimeout 60000` 复跑后全部通过。网页 Vite 构建通过。
- `scripts/test-lan.cjs` 的真实双客户端回归通过，包含房主权限、重连与座位恢复；`scripts/test-unity-room.cjs` 的 Unity 房间协议、房主专属操作、部署与倒地动作等回归通过。这两项测试仅在本机临时端口运行。
- Unity 菜单 `IRONFRONT/Build macOS Standalone` 构建成功，`UnityProject/Builds/macOS/IRONFRONT.app` 的 `Info.plist` 版本为 `0.32.0`。独立程序位于本机构建目录，未纳入 Git。

## 当前限制

布局面向桌面横屏窗口；极窄或竖屏画面尚未专门适配。模型预览复用当前 Unity 低多边形人物，因此其精度取决于现有战场模型。赤砂走廊与攻防模式仍处于设计阶段，没有可进入的战局。LAN 房间入口仅沿用已有流程，本次未进行跨设备联机验收。

开发与提交保留在 `codex/unity-port`，不合并 `main`。
