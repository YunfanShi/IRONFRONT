# 0.38.0 Unity 还原对照与单人攻防首轮

本表持续更新；0.39.0 单人闭环首轮的改动和验收边界见 [UNITY_SOLO_MATCH_FLOW_039.md](UNITY_SOLO_MATCH_FLOW_039.md)。

## 完成标准

网页端以本分支 `src/` 的现有可玩功能为参照，不把 `FurtherPlan.md` 中尚未落地的新地图、新载具和新模式计入“原版还原”。`0.38.0` 是开发版本号，不代表还原百分比。以下状态只按可运行代码与当前验收记录填写：**通过**表示该项完整场景已在 Unity 验收；**局部**表示已有实现但场景或范围不全；**缺失**表示 Unity 没有相应玩法；**待验**表示代码已接入但尚缺完整实战验收。

单人还原完成的门槛：在 macOS 独立程序中，从菜单选择模式和规模，以四兵种完成工业前线的征服与攻防战局；八类原版载具能按各自席位、武器、损毁和复活规则参与；双方 AI 能完成目标、支援与载具协同；一局从部署、战斗、复活到有效胜负无阻断；所宣称人数规模有实测性能证据。每项通过后才标为“已还原”。联机另设门槛，不用本机房间协议测试冒充跨机战斗验收。

## 本轮改动与验证

- `PrototypeMatch` 加入单人征服/攻防模式、当前进攻据点、红方无限票、蓝方夺点加 40 票（不超过开局票数）、蓝方耗票/夺完五点的胜负规则及 900 秒后缓慢耗票。占领速度与原版 `Conquest.ts` 相同。
- `PrototypeCommander` 在攻防中仅分配当前据点；推进后立即重新计划。菜单可以选择模式，并用 `M` 键切换；选择写入本机 `PlayerPrefs`。HUD 显示红方无限票并高亮当前据点。LAN 仍只运行现有征服协议。
- Unity 6000.5.10f1 的 `Assets → Refresh` 后 Console 无编译错误；编辑器菜单 `IRONFRONT → Verify Solo Match Rules` 输出 `IRONFRONT solo match rules PASS`，覆盖两种模式起点、非活动区限制、票数、逐点推进与双方胜负。
- 在 Unity Play 中按 `M` 选攻防、Enter 开局，目视看到所有点初始归红方、A 高亮、红方票数为无限、双方小队向 A 下令；随后在部署界面看到 A 变蓝。`IRONFRONT → Verify Tank and Respawn` 在这局中输出 `IRONFRONT smoke PASS`，Console 0 警告、0 错误。此处不等于五点人工长局已通过。
- 2026-10-11 用 Unity 6000.5.10f1 成功构建 `UnityProject/Builds/macOS/IRONFRONT.app`，应用版本为 `0.38.0`。实际启动独立程序，在菜单按 `M` 切到攻防、Enter 进入战斗，目视确认五点归红、A 高亮、蓝方 100 票、红方无限票、双方小队命令指向 A。此次是开局验收，尚未完成 A–E 整局。
- TypeScript 主配置 `tsc --noEmit`、逻辑配置 `tsc -p tsconfig.logic.json` 均通过；`node scripts/test-unity-room.cjs` 的 Unity 房间协议回归通过。它们分别验证网页类型与房间消息，不构成 Unity 玩法或两机联机验收。
