# 0.23.0 Unity R4 侦察车切片

## 目标与基线

本轮从 `codex/unity-port` 的 `efb762f`（0.22.0）继续。此前 Unity 已有单地图征服短局、四兵种、小队战术、出击界面和 macOS 构建入口，但没有可驾驶载具。本轮先移植网页游戏的 R4 侦察车，验证车辆导航、进出车、战斗和独立程序能连成一条可运行流程。按 `ForAgent.md` 新模块规则升至 0.23.0；用户要求 Unity 二次开发保留在独立分支，所以继续使用 `codex/unity-port`，不合并 `main`。

## 实现范围

- 新增 `PrototypeScoutVehicle.cs` 和 `.meta`。蓝方侦察车停在步兵出生点附近，红方侦察车由 AI 控制；双方均有 180 点车体生命。占位模型包含车身、四轮及可转向机枪塔。
- 玩家在距蓝车 5.5 米内按 E 上车，再按 E 下车。车内停用步兵移动与射击，切换第三人称追车镜头；下车恢复步兵控制、第一人称镜头和步枪。车辆被毁、玩家死亡或战局结束时强制离车。下车位置先检测地形和物理碰撞，附近都不安全时退回已知可用出生点。
- 车内 WASD 油门与转向、鼠标瞄准、左键机枪。车辆移动逐段检查 2.1 米净空；红方 AI 使用相同净空的 45×45 A* 路线和路段平滑，不复用仅适合步兵的窄路径。AI 优先选择未归属己方且可到达的据点，并只向可见敌人开火。
- 步兵可射击敌方侦察车；AI 会把正在驾驶或 AI 控制的敌车当作威胁，避免出击前就攻击无人蓝车。车毁后关闭碰撞和模型、驾驶员离车，并按网页征服规则扣该队 0.5 票。出击页与 HUD 更新操作说明、车况与速度；桌面大视口提高 UI 缩放。
- 编辑器构建入口现在检查十一个运行时脚本。网页包版本、房主状态、客户端版本门槛和菜单展示同步到 0.23.0；网页与 Unity 仍没有跨端联机协议，更新网页房主服务后须重启服务。

## 验证记录

- 本机 Unity 6000.5.10f1 随附 Roslyn 使用 UnityEngine 与 .NET Standard 2.1 引用静态编译十一个运行时脚本，通过。
- Unity 编辑器实际刷新并 Play `SampleScene`：出击界面列出 E 控制；进入蓝车后看到车尾第三人称视角、`R4 SCOUT` 装甲/速度及车内控制提示，战局票数和 AI 持续运行。正式源码刷新后 Console 0 错误、0 警告。
- 为区别极短自动键击与持续驾驶，在编辑器运行场景临时调用车体实际 `Drive` 方法，以 12 次 0.05 秒前进输入测得车体移动 2.535 米、末速度 7.8 m/s。临时探针脚本及其 `.meta` 随后删除，刷新后菜单中已消失。这个检查验证真实 Unity 车体位移和当前出生点净空，不等同于人持续按 W 的完整驾驶验收。
- 从 Unity 菜单重新构建 macOS Standalone，Console 显示 `IRONFRONT macOS build succeeded`，产物约 116.6 MB；最终产物 `Info.plist` 的版本号为 0.23.0。实际启动构建，看到出击页、战场、上车后的车辆模型与车况 HUD；Player.log 未检出 `error` 或 `exception`。
- 网页回归通过：严格 TypeScript、Vitest 13 个文件 117/117 项、Vite 生产构建、8/16/32/64 人和默认战局核心模拟、真实双客户端 LAN 集成回归。Vite 仍提示既有 Three.js 分块约 502 kB。

## 当前限制与后续

目前处于车辆移植阶段的第一辆车切片。尚未实测持续人工按键驾驶、机枪命中完整流程和多局平衡；独立程序中的 E 下车、车辆损失票数和 AI 长路线仍需针对性复测。蓝车静止停在战线附近可能被推进的红方火力摧毁，玩家应尽快驾驶离开。其他七类载具、席位、配装、正式模型、完整模式选择、局域网房间和跨机联机都尚未移植。网页 LAN 回归只验证网页端。下一步应先完成侦察车的人工驾驶与战斗验收，再抽出共用车辆底盘和席位规则，之后做其他车型及 Unity 网络权威状态。
