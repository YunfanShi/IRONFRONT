# 0.20.0 Unity 小队指挥与有限情报

## 目标与基线

本轮继续 `codex/unity-port` 分支中的 Unity 移植。开始时本地与 GitHub 开发分支均在 `c1ac5b9`，版本为 `0.19.1`；`main` 已恢复移植前的网页游戏文件。此前 Unity 原型中的八名 AI 固定前往 B/C 两个据点，无法随着占领和战斗变化重新分配目标。本轮按 `ForAgent.md` 的新功能规则升至 `0.20.0`，保持 Unity 代码只在开发分支。

## 实现

- 新增 `PrototypeCommander.cs`，蓝红双方各持有两支双人小队。指挥官每 4 秒评估五个据点的归属、争夺状态、实际距离、已分配的小队数量、队员存活数量和近期路线失败，发布夺取、防守或增援任务。小队通常保留任务至少 12 秒，已证实的己方据点争夺与寻路失败可提前打断。
- 士兵只把视线无遮挡时发现的敌人位置作为目击报告传给本队指挥官。报告最多保留 16 条、24 秒过期；近距离重复目击会合并。指挥官只拿到坐标和时间，不接收敌方实体、实时全场敌人列表或能查询隐藏位置的回调。全场据点归属与争夺状态沿用现有公开战局状态。
- 每支小队的两名士兵在据点周围使用不同站位，避免完全重叠。每次命令变更清除旧路线；遇到无路线或持续无进展时停止盲目前冲并上报，使指挥官临时避开该据点。失败据点保留 18 秒冷却；多个失败目标可以同时记录。
- HUD 右上角显示双方各两支小队的目标、任务和存活人数。HUD 根据 Game 窗口的逻辑分辨率缩放；编辑器设为 2x 时，命令面板和底部操作提示不再重叠。Unity 原型仍由场景自动启动，玩法输入保持原样。
- 网页程序本身没有新增 AI 玩法；仅将包、菜单标识、房主状态接口与客户端房间版本门槛同步到 `0.20.0`。更新网页房主时需重启服务，`0.19.x` 与 `0.20.x` 房间不互通。

## 验证

- 用本机 Unity 6000.5.10f1 安装包附带的 Roslyn、.NET Standard 2.1 与 UnityEngine 程序集静态编译全部七个 Unity C# 文件，通过。这能验证语法与引用，不能替代 Unity Play。
- 另用独立 .NET 场景桩运行真实 `PrototypeCommander.cs`：验证初始分兵、占领后向其他据点推进、路线失败改派、己方据点被争夺时增援，以及目击报告能影响防守选择，五项通过。场景桩不模拟 Unity 物理和长局战斗。
- 在本机 Unity 6000.5.10f1 中刷新脚本并实际 Play `SampleScene`：Hierarchy 出现原型运行对象，双方小队 HUD 初始分别指向 B/C；继续运行后红队命令转向 A，据点进度、票数、HP 和存活人数更新，Console 0 错误、0 警告。2x Game 窗口下复测 HUD，左右面板及底部操作提示不再重叠。此项是编辑器短时运行验收，尚未完成独立构建或长期平衡测试。
- 网页 TypeScript 检查、117/117 单元测试、生产构建及双客户端 LAN 自动回归通过。LAN 测试需要本机临时回环端口，因此在允许端口监听的环境运行。生产构建仍有 Three.js 分块略超 500 kB 的既有提示。具体结果见根目录 `QA_REPORT.md`。

## 当前范围

这一步移植的是小队任务分配和有限情报边界，不等于网页 AI 全部功能已经移植。Unity 版本仍无兵种、治疗/补给、掩体预留、载具驾驶、指挥建议、完整难度配置或 LAN 联机；这些需要后续独立实现和验证。现有战场仍是单地图 100 票短局。
