# 0.39.3 Unity 坦克高帧率起步修复

## 目标与基线

本轮继续 0.39.2 的 [坦克操控修复](UNITY_TANK_CONTROLS_0392.md)。用户追问“初始速度为 0 是否永远为 0”后，检查 `PrototypeTankVehicle.Drive` 发现一个此前低帧率烟测没有覆盖的高帧率死区。开始时分支为 `codex/unity-port`，`HEAD` 为 `973c5ab`，仓库及 macOS 独立程序均显示 0.39.2。六个 Unity 设置/渲染资产有既存编辑器序列化改动，本轮不将它们并入修复。

## 复现与原因

`Drive` 每帧先执行 `Mathf.MoveTowards(Speed, target, 5 * dt)`，再把绝对值小于 `0.05` 米/秒的速度清零。从静止按 W 时，100 FPS 的一帧为 0.01 秒，新增速度恰好为 0.05 米/秒；高于 100 FPS 时，一帧新增量低于 0.05，立刻被清零。下一帧又从 0 开始，因而坦克可在高帧率下持续按 W 却永远无法起步。此条件与鼠标锁定、炮弹装填和地图碰撞相互独立。

旧编辑器烟测用 `dt = 0.05` 秒调用驾驶方法，等效 20 FPS；新增量 0.25 米/秒，无法发现这个问题。0.39.2 独立程序操作中快速短按 W 后看到速度 0，也不足以区分输入时间太短与此高帧率问题。

## 修改

- 删除移动后的小速度强制清零。`Mathf.MoveTowards` 在松开油门时已经会精确趋近到 0，无需额外死区。
- 在同一个编辑器坦克烟测中，从入座后的静止状态，以 `1/240` 秒帧时长连续模拟 60 帧 W 油门，检查车速大于 0 且车身位移超过 0.1 米。旧代码在第一帧反复归零，新增断言会失败；修复后应通过。
- 按小问题修复规则将仓库、网页/服务端显示和 Unity 应用版本一并更新为 0.39.3。此版本不改变 [Unity 还原对照](UNITY_PARITY_038.md) 中 S1/S2/S8 的局部状态。

## 验证记录

| 环境 | 实际结果 | 验证范围 |
| --- | --- | --- |
| 编辑器 Play，`IRONFRONT → Verify Tank and Respawn` | 第二次运行显示 `IRONFRONT smoke PASS`，Console 为 2 条信息、0 警告、0 错误 | 高帧率静止起步与原有驾驶、炮弹、复活烟测 |
| macOS 独立程序构建 | Unity Console 显示 `IRONFRONT macOS build succeeded`，0 警告、0 错误；`Info.plist` 的 `CFBundleShortVersionString` 为 0.39.3；启动后大厅显示 0.39.3 | 新构建和应用版本 |
| 独立程序持续按住 W | 待验 | 人工输入下的实际长按驾驶；自动界面工具仅能短按 |

本轮的高帧率回归检查调用真实的坦克驾驶方法，但它仍属于编辑器内的模拟输入。独立程序中的持续按键和不同地形位置需分开验收，不能用模拟输入替代。

第一次 Play 运行的烟测在准备阶段报 `friendly T90 exists`，未进入新增断言；退出并重新进入 Play 后，场景层级中有蓝、红两辆 T90，完整烟测通过。首次运行还出现一条 Unity 场景引用脚本缺失警告；第二次运行未出现。此现象尚未定位，不计作高帧率起步回归结果。

首次点击构建时 Unity 提示脚本仍在编译，待编译结束后重新执行构建并成功。
