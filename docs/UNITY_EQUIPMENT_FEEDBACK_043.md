# 0.43.0 Unity 装备模型与战斗反馈

## 目标与现状

这轮针对 Unity 单人及房主权威战局的装备反馈。原有七种枪械虽能开火，但大多共用一套模型；破片弹和烟雾弹在战场上只是简单球体；工程兵的火箭以射线即时命中，没有可见飞行弹体。唯一已接入的枪声是玩家卡宾枪读取的 `carbine.wav`，坦克炮、载具机枪、其他枪械和爆炸没有对应音效。原破片弹已用半径搜索，但目标类型之间的伤害衰减不一致。

## 装备与模型

| 装备 | 0.43.0 变化 |
| --- | --- |
| 七种枪械 | 保留低多边形风格，手枪改为独立的短枪结构；冲锋枪增加折叠枪托和枪口护罩；轻机枪增加弹箱、提把与两脚架；狙击枪增加长枪管、枪栓和两脚架；战斗步枪增加侧导轨和重型枪口制退器。已有的卡宾枪与精确射手步枪保留各自的枪管、瞄具和弹匣轮廓。第一人称和菜单预览共用模型生成逻辑。 |
| 四兵种装备 | 突击兵佩戴弹药包和弹匣，医疗兵佩戴医疗包与十字标识，侦察兵佩戴信标筒与天线，工程兵背负火箭发射器及维修工具。装备随士兵模型显示，菜单预览也显示对应兵种装备。 |
| 破片弹、烟雾弹 | 投掷物有弹体、环带、保险杆和拉环；破片弹有纵向凸棱，烟雾弹有泄烟口。投掷期间以带碰撞体和刚体的模型飞行。 |
| 火箭与发射器 | 工程兵发射时短暂显示发射器，火箭是可见的弹头、推进段及尾翼，按弹道飞行并在碰撞或射程终点爆炸。侦察兵的地面信标增加天线和指示灯。 |

## 声音、特效与伤害

- `PrototypeCombatFeedback` 为七种枪械、坦克炮及爆炸接入仓库内网页原版音频；载具机枪、手雷投掷、烟雾释放、火箭发射以及弹药包、医疗包、装甲工具、信标使用按装备类型生成的声音。缺少原版素材时会回退到缓存的合成波形。音源按射手位置做 3D 距离衰减，本地玩家的枪声保持可听。
- 步兵枪、载具机枪、坦克炮和火箭发射时出现短暂枪口闪光；普通弹命中有火花。炮弹、火箭、破片弹和载具损毁触发有亮核、径向碎屑和短暂照明的爆炸效果及相应声音。烟雾弹释放数团持续约 8 秒的烟雾；兵种能力使用时有短暂视觉提示和角色类型声音。
- 破片弹以落点为中心搜索 **5.5 米**内目标，按最近碰撞点到爆心的距离线性衰减。敌方 AI、联机远端玩家和载具使用同一半径与衰减规则；维持现有不伤友军规则。火箭爆炸半径为 **4.5 米**，载具最大伤害 **210**，步兵最大伤害 **90**，同样按距离衰减。坦克炮沿用原本 4.5 米爆炸与伤害逻辑，并补上声音和特效。

## 验证

- Unity 6.5.10f1 在 `SampleScene` Play 中运行 `IRONFRONT → Verify Equipment and Effects`：检查七种枪与四兵种装备的场景模型、两类手雷及火箭/发射器模型；把敌人与友军分别放在破片弹半径内外，验证敌方近处受伤、远处不受伤、友军不受伤；实际触发 T90 炮击，检查物理炮弹、网页原版炮声音源正在播放与枪口反馈。Console 输出 `IRONFRONT equipment PASS`，无报错。
- 原有 `Verify Ballistics` 与 `Verify Tank and Respawn` 均通过。网页 TypeScript 检查与 `verify-core.cjs` 通过。Unity 构建 `UnityProject/Builds/macOS/IRONFRONT.app` 成功，包版本为 `0.43.0`；本机重新签名后 `codesign --verify --deep` 通过。
- 独立程序尚未完成画面与听感验收：本机的 macOS 应用注册服务在进程启动时崩溃，调用栈与 0.42.0 构建相同；`open` 启动本程序和系统 Calculator 均返回 `kLSNoExecutableErr`，故无法把该机器上的独立程序启动失败归因于本轮游戏代码。需要在可正常打开应用的 macOS 环境中人工检查音量、声音层次和特效可读性。程序化低多边形模型仍可按最终美术目标替换。
